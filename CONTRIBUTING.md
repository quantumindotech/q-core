# Contributing to Q-CORE

## Before contributing

1. Read the README and the relevant architecture documents.
2. Confirm that you have the right to submit the proposed material.
3. Identify third-party, generated, AI-assisted, copied, or adapted material.
4. Do not submit credentials, private keys, seed phrases, personal data, or confidential operational information.

## Changes

- Keep changes scoped and reviewable.
- For architectural or cross-project changes, include an ADR.
- Include a test plan and reproducible evidence for behavior changes.
- Document assumptions, limitations, and unresolved risks.
- Do not describe a feature as implemented, secure, quantum-resistant, or production-ready without evidence.

## Provenance

Every contribution must identify its origin and applicable license. Unknown or disputed provenance must be marked `PROVENANCE_PENDING` and must not be redistributed as cleared project code.

Submitting a contribution does not by itself transfer copyright or grant rights beyond the applicable license. Any separate assignment or contributor agreement must be explicit and documented.

## Pull requests

A pull request should state:
- purpose and scope;
- files and components affected;
- provenance and license information;
- tests performed and results;
- security and compatibility implications;
- evidence and known limitations.
